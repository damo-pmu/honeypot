# Feature 5.2: IOC Storage in Database

## Overview
Persistent storage for Indicators of Compromise (IOCs) detected in honeypot traffic, with deduplication and relationship mapping to attackers and sessions.

## Components

### 1. IOCIndicator Entity (`src/core/entities/models.py`)
```python
class IOCIndicator(BaseModel):
    ioc_type: str  # hash, ip, domain, url
    value: str
    first_seen: datetime
    last_seen: Optional[datetime]
    confidence: float = 1.0
    source: str = "scan"
    hit_count: int = 1
    related_attacker_ip: Optional[str]
    related_session_id: Optional[str]
```

### 2. Database Schema (`migrations/001_create_ioc_table.sql`)
- Table `ioc_indicators` with indexes on value, type, and hit_count
- Unique constraint on (ioc_type, value) for deduplication
- Foreign key relationships to attackers and sessions

### 3. API Endpoints (`src/api/endpoints/ioc.py`)

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/ioc/scan` | POST | Scan text for IOCs |
| `/ioc/store` | POST | Store IOC with deduplication |
| `/ioc/top` | GET | Get top IOCs by hit count |
| `/ioc/type/{type}` | GET | Filter IOCs by type |
| `/ioc/search/{value}` | GET | Search IOC in commands/payloads |
| `/ioc/bulk-scan` | POST | Bulk insert with dedup |

### 4. Database Queries (`src/infrastructure/database/queries.py`)

- `create_ioc()` - Insert new IOC
- `get_ioc_by_value()` - Check for existing IOC (deduplication)
- `increment_ioc_hit()` - Update existing IOC hit count
- `get_top_iocs()` - Leaderboard of most detected IOCs
- `get_iocs_by_type()` - Filter by type
- `search_ioc_in_commands()` - Find IOC in command history
- `search_ioc_in_payloads()` - Find IOC in attack payloads

## IOC Types Detected
- **Hashes**: MD5 (32), SHA1 (40), SHA256 (64) character hex strings
- **IPs**: IPv4 addresses
- **URLs**: HTTP/HTTPS URLs
- **Domains**: (requires source enrichment)

## Integration Flow
```
1. Cowrie worker captures attack payload
2. IOC scanner extracts indicators
3. Check if IOC exists in DB
4. If exists → increment hit_count
5. If new → insert with attacker/session link
6. Expose via API for forensics
```
